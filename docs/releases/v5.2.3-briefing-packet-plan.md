# v5.2.3 Briefing Packet Plan (Next Workday)

Purpose: complete a reliable "Send Briefing Packet" flow that gives both AI threads project/session context from four sources:

- manually typed primer document (from built-in notepad flow);
- post-session recap document (auto-generated);
- workspace file tree output;
- master axiom file content.

All recap/briefing artifacts should be written as simplified LaTeX-style Markdown in the workspace root so users can inspect them quickly.

## Why this milestone matters

This is a real reliability milestone for AI context quality. If the packet is complete and deterministic, both Ollama threads can reason from the same project ground truth.

## Existing building blocks (already in repo)

- UI trigger exists: `sendAIStateBriefing()` button in the right wing context panel.
- Backend command exists: `compile_ai_briefing` in Rust.
- File tree export exists: `export_workspace_tree` command and frontend wiring.
- Axiom generation exists: `generate_master_axiom_from_theory` command and UI status updates.
- Manual note save exists: scratchpad save flow (`saveScratchpad` -> `save_scratchpad_content`).

## Gap to close tomorrow

Current `compile_ai_briefing` builds a JSON state/template but does not yet assemble a concrete packet from:

1. user-authored primer file content,
2. post-session recap file content,
3. actual exported tree text,
4. actual master axiom file text,
5. per-thread dispatch payload to both AI panes.

## Implementation target

### 1) Define packet schema

Add a stable JSON payload structure from `compile_ai_briefing`, for example:

- `status`
- `project_root`
- `session_goal` (optional text field)
- `primer`:
  - `path`
  - `content`
- `session_recap`:
  - `path`
  - `content`
- `workspace_tree`:
  - `path`
  - `content`
- `master_axiom`:
  - `path`
  - `content`
- `summary` (short generated digest for token-efficient prompts)

### 2) Resolve source files deterministically

Use config + workspace defaults to resolve:

- primer path (default to workspace root `scratchpad.md` unless explicit path added);
- recap path (default to workspace root `session_recap.md`);
- workspace tree path (default to workspace root `workspace_tree.txt`);
- master axiom path (existing config field).

All generated briefing artifacts should default to workspace root paths (not nested app subfolders):

- `session_recap.md`
- `ai_briefing.md`
- `workspace_tree.txt`

If a source is missing, return explicit diagnostics instead of silent success.

### 3) Read and package content in Rust

Inside `compile_ai_briefing`:

- read resolved files,
- include plain text content in payload,
- include line/size metadata,
- cap oversized content with clear truncation markers.

For markdown artifacts, keep syntax simple and AI-friendly:

- standard headings,
- short bullet lists,
- inline/simple LaTeX where useful,
- minimal ornamentation.

### 4) Frontend dispatch to both AI threads

In `sendAIStateBriefing()`:

- call `compile_ai_briefing`,
- parse payload,
- post a concise packet summary to terminal log,
- send packet-derived system/context prompt to left and right threads,
- display actionable status in the context panel.

### 5) Error handling

- no `alert`-only success path,
- show source-level failures (missing primer, unreadable axiom, empty tree),
- keep partial packet behavior explicit (`status: partial`).

## Acceptance criteria

- Clicking Send Briefing Packet updates both AI threads with the same packet summary.
- Packet includes real content from primer, recap, tree, and master axiom sources.
- Missing source files are clearly reported with fix hints.
- Terminal log shows what was loaded and from where.
- No silent failures.
- Recap and briefing markdown files are generated/updated in workspace root.

## Suggested test script (manual)

1. Load a workspace with theory files.
2. Save scratchpad note content to `scratchpad.md`.
3. End session once to generate/update `session_recap.md` (or create a test recap).
4. Generate or point to a master axiom file.
5. Export workspace tree.
6. Click Send Briefing Packet.
7. Verify both AI panes receive context and can reference all four sources.
8. Confirm `ai_briefing.md` exists in workspace root and is readable markdown.
9. Remove one source file and confirm user-visible diagnostic behavior.
